# Private handoff review (implementation draft)

This feature stores untrusted historical handoff evidence separately from RSSD works, demands, submissions and publications. Each review entry has a new random ID. The legacy request key remains private evidence and must never be used as a new Center submission ID or as permission to retry or publish.

`RssdPrivateReview.stage` is an internal method only. There is deliberately no HTTP, MCP or device route for staging or promotion. A future importer must authenticate the operator, independently verify the source archive, inventory, organization/site/workspace mapping and every source byte, preserve the original archive, and submit only validated material. It must not accept a caller-provided digest as proof of provenance. Existing exact request identities must be reconciled with all original systems before any later action.

The read-only `/rssd/v1/private-review/:workspaceId` and item/file routes use the existing RSSD/Postiz middleware. The service requires an owner user session, rejects device credentials, scopes each query to the session organization and workspace, and records minimal successful-access audit entries in the same transaction before returning data. Lists omit legacy identities and private content. Private files are sent as generic attachments with no-store and no-sniff headers; site-facing public routes expose no review records.

This is not deployment-ready: the verified bundle importer and provenance store, administrative UI, pagination, operational reconciliation/promotion workflow, detailed audit retention, storage limits/backup policy and full Postiz production-session/tenant tests remain to be designed. The new additive tables require a reviewed migration and deployment/rollback procedure; PostgreSQL roles, backups, static builds, logs, analytics and downstream exports must not expose their contents. Do not stage any real archive or activate these routes until those gates pass.
