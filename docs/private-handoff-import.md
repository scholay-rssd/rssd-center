# Private handoff import (review candidate)

This implementation is disabled by default. It creates only private `needs_reconciliation` records; it never claims work, publishes, replays an old request through a new API, or overwrites a conflicting record. It is not yet approved for production use.

A Postiz administrator issues a five-minute, single-scope grant for an organization, workspace, site and source archive SHA-256. The token is displayed once, stored only as a hash and delivered to the local CLI over an owner-only Unix socket. Role checks run in a short-lived child process with an eight-second deadline; Postiz startup does not wait. On timeout the child is killed and reaped, and any late socket is closed. Startup or runtime failures disable only the private import component and surface an administrator-only status. A stale socket is not removed automatically: the component remains unavailable until an operator confirms and clears it. A trusted internal source loader verifies the original archive directly, checks every manifest-listed business file, preserves the original compressed bytes, and records any allowed package-metadata differences explicitly as `package_metadata_mismatch`. The grant binds an explicit generic source profile; only individually declared package-level metadata differences with exact expected and actual hashes can be recorded, and no business file or referenced evidence may be excepted. All other differences fail closed. The CLI reads its input configuration from descriptor 3 and prints aggregate status rather than original keys or text.

The separate worker has no direct private-table privileges. Its SECURITY DEFINER functions check the grant, live organization membership, exact workspace and site, original request and article identities, each required file and its bytes, and original prepared/receipt identities. Staged data and redacted audit are committed together. Identical requests resume without duplication; conflicting identities fail. Existing identical private-review records retain their original IDs. The owner can revoke a grant and authorize a fresh one for the same immutable archive.

`rssd/private-import-secure-policy.sql` is an explicit DBA-reviewed role policy, not an automatic application migration. It creates non-login function-owner roles, a restricted worker role, a grant-issuer role and a separate trusted source-loader role. An administrator must classify each exceptional root-level file as package-only metadata; the verifier rejects all evidence references but cannot determine the semantic purpose of an unreferenced root file. The source loader can directly read and insert private source evidence across organizations; it must run only as trusted Center infrastructure and must never be given to a device or an untrusted worker. The authentication function owner has column-level UPDATE privilege required for PostgreSQL row locks, but its static function exposes no mutation operation. Production login-role membership and backend access must be granted explicitly after review.

The three private database URLs use separate issuer, trusted source-loader and worker roles. Before enabling this candidate, review deployment and least-privilege role ownership on the actual Postiz database; verify real session and organization authorization without test stubs; provide protected credential delivery, operator UI for the mismatch and reconciliation status, cancellation and audited provenance access; assess source-loader tenant trust and resource limits; prove database/WAL/disk capacity under concurrency; and verify public API, exports, logs and rollback using an isolated production-like environment. Archive verification runs asynchronously outside the Nest event loop. The initial limits are 32 MiB compressed, 128 MiB expanded, 5,000 archive entries, 16 MiB for either metadata document, a 48 MiB socket frame and 64 MiB verifier output. The verifier still buffers data in memory and duplicates selected bytes in PostgreSQL; larger packages require a separately reviewed split or dedicated offline flow; this implementation does not automatically split them. An interrupted import is not a completed reconciliation. No production cutover or public publication is implied by a successful test.

The CI workflow creates a separate disposable `rssd_import_test` database for `node --test rssd/private-import-secure.test.mjs` and runs `python3 -m unittest discover -s rssd -p test_private_import_archive.py -v`. Tests use synthetic material. The Nest route tests use actual compiled middleware and JWT handling with stubbed Postiz user/organization services; they do not prove a live Postiz session.

On macOS and Linux, the reader opens its input without following symlinks and with nonblocking mode, then rejects anything other than a regular file. The isolation tests verify FIFO rejection and kill the caller during a large synthetic archive verification. Individual filesystems can still experience uninterruptible I/O, and abrupt host loss may leave incomplete work; startup and recovery require operator verification.
